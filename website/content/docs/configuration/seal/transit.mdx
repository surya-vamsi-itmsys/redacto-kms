# `transit` seal

:::info

This mechanism is built into Redacto KMS and does not require an external KMS
provider plugin.

:::

The Transit seal configures Redacto KMS to use Redacto KMS's Transit Secret Engine as the
autoseal mechanism.
The Transit seal is activated by one of the following:

- The presence of a `seal "transit"` block in Redacto KMS's configuration file
- The presence of the environment variable `REDACTO_KMS_SEAL_TYPE` set to `transit`.

## `transit` example

This example shows configuring Transit seal through the Redacto KMS configuration file
by providing all the required values:

```hcl
seal "transit" {
  address            = "https://openbao:8200"
  token              = "s.Qf1s5zigZ4OX6akYjQXJC1jY"
  disable_renewal    = "false"

  // Key configuration
  key_name           = "transit_key_name"
  mount_path         = "transit/"
  namespace          = "ns1/"

  // TLS Configuration
  tls_ca_cert        = "/etc/openbao/ca_cert.pem"
  tls_client_cert    = "/etc/openbao/client_cert.pem"
  tls_client_key     = "/etc/openbao/ca_cert.pem"
  tls_server_name    = "openbao"
  tls_skip_verify    = "false"
}
```

## `transit` parameters

These parameters apply to the `seal` stanza in the Redacto KMS configuration file:

- `address` `(string: <required>)`: The full address to the Redacto KMS cluster.
  This may also be specified by the `REDACTO_KMS_ADDR` environment variable.

- `token` `(string: <required>)`: The Redacto KMS token to use. This may also be
  specified by the `REDACTO_KMS_TOKEN` environment variable.

- `key_name` `(string: <required>)`: The transit key to use for encryption and
  decryption. This may also be supplied using the `REDACTO_KMS_TRANSIT_SEAL_KEY_NAME`
  environment variable.

- `mount_path` `(string: <required>)`: The mount path to the transit secret engine.
  This may also be supplied using the `REDACTO_KMS_TRANSIT_SEAL_MOUNT_PATH` environment
  variable.

- `namespace` `(string: "")`: The namespace path to the transit secret engine.
  This may also be supplied using the `REDACTO_KMS_NAMESPACE` environment variable.

- `disable_renewal` `(string: "false")`: Disables the automatic renewal of the token
  in case the lifecycle of the token is managed with some other mechanism outside of
  Redacto KMS, such as Redacto KMS Agent. This may also be specified using the
  `REDACTO_KMS_TRANSIT_SEAL_DISABLE_RENEWAL` environment variable.

- `tls_ca_cert` `(string: "")`: Specifies the path to the CA certificate file used
  for communication with the Redacto KMS server. This may also be specified using the
  `REDACTO_KMS_CACERT` environment variable.

- `tls_client_cert` `(string: "")`: Specifies the path to the client certificate
  for communication with the Redacto KMS server. This may also be specified using the
  `REDACTO_KMS_CLIENT_CERT` environment variable.

- `tls_client_key` `(string: "")`: Specifies the path to the private key for
  communication with the Redacto KMS server. This may also be specified using the
  `REDACTO_KMS_CLIENT_KEY` environment variable.

- `tls_server_name` `(string: "")`: Name to use as the SNI host when connecting
  to the Redacto KMS server via TLS. This may also be specified via the
  `REDACTO_KMS_TLS_SERVER_NAME` environment variable.

- `tls_skip_verify` `(bool: "false")`: Disable verification of TLS certificates.
  Using this option is highly discouraged and decreases the security of data
  transmissions to and from the Redacto KMS server. This may also be specified using the
  `REDACTO_KMS_SKIP_VERIFY` environment variable.

- `disabled` `(string: "")`: Set this to `true` if Redacto KMS is migrating from an auto seal configuration. Otherwise, set to `false`.

Refer to the [Seal Migration](../../concepts/seal.mdx#seal-migration) documentation for more information about the seal migration process.

## Authentication

Authentication-related values must be provided, either as environment
variables or as configuration parameters.

:::warning

**Note:** Although the configuration file allows you to pass in
`REDACTO_KMS_TOKEN` as part of the seal's parameters, it is _strongly_ recommended
to set these values via environment variables.

:::

The Redacto KMS token used to authenticate needs the following permissions on the
transit key:

```hcl
path "<mount path>/encrypt/<key name>" {
  capabilities = ["update"]
}

path "<mount path>/decrypt/<key name>" {
  capabilities = ["update"]
}
```

Other considerations for the token used:
* it should probably be an [orphan token](../../concepts/tokens.mdx#token-hierarchies-and-orphan-tokens),
otherwise when the parent token expires or gets revoked the seal will break.
* consider making it a [periodic token](../../concepts/tokens.mdx#periodic-tokens)
and not setting an explicit max TTL, otherwise at some point it will cease to be renewable.

## Key rotation

This seal supports key rotation using the Transit Secret Engine's key rotation endpoints. See
[doc](../../api/secret/transit.mdx#rotate-key). Old keys must not be disabled or deleted and are
used to decrypt older data.
