# Kubernetes

Redacto KMS can be deployed into Kubernetes using the official Redacto KMS Helm chart.
The Helm chart allows users to deploy Redacto KMS in various configurations:

- Dev: a single in-memory Redacto KMS server for testing Redacto KMS
- Standalone (default): a single Redacto KMS server persisting to a volume using the file storage backend
- High-Availability (HA): a cluster of Redacto KMS servers that use an HA storage backend
- External: a Redacto KMS Agent Injector server that depends on an external Redacto KMS server

## Use cases

**Running a Redacto KMS Service:** The Redacto KMS server cluster can run directly on Kubernetes.
This can be used by applications running within Kubernetes as well as external to
Kubernetes, as long as they can communicate to the server via the network.

**Accessing and Storing Secrets:** Applications using the Redacto KMS service running in
Kubernetes can access and store secrets from Redacto KMS using a number of different
[secret engines](../../secrets/index.mdx) and [authentication methods](../../auth/index.mdx).

**Running a Highly Available Redacto KMS Service:** By using pod affinities, highly available
backend storage and [auto-unseal](../../concepts/seal.mdx#auto-unseal),
Redacto KMS can become a highly available service in Kubernetes.

**Encryption as a Service:** Applications using the Redacto KMS service running in Kubernetes
can leverage the [Transit secret engine](../../secrets/transit/index.mdx)
as "encryption as a service". This allows applications to offload encryption needs
to Redacto KMS before storing data at rest.

**Audit Logs for Redacto KMS:** Operators can choose to attach a persistent volume
to the Redacto KMS cluster which can be used to [store audit logs](../../audit/index.mdx).

**And more!** Redacto KMS can run directly on Kubernetes, so in addition to the
native integrations provided by Redacto KMS itself, any other tool built for
Kubernetes can choose to leverage Redacto KMS.

## Getting started with Redacto KMS and kubernetes

There are several ways to try Redacto KMS with Kubernetes in different environments.

### High level comparison of integrations

There are currently 2 different integrations to help Kubernetes workloads
seamlessly consume secrets from Redacto KMS, without the need to modify the
application to interact directly with Redacto KMS. Each integration addresses
slightly different use-cases. The following is a brief overview of the strengths
of each integration.

#### Agent injector

- No durable secret storage outside Redacto KMS. All secrets written to disk are in ephemeral in-memory volumes.
- No highly privileged service accounts required. All secrets are fetched with the pod's own service account without the need for any other service accounts to impersonate it.
- More mature solution, with proven production record and advanced features like templating,
  wider array of auth methods, etc.
